Host a server

The server archive runs the same engine as the client, headless, with a supervisor around it.

The archive

curse-server-linux-x86_64.tar.gz holds the supervisor (curse-server), the engine (curse-engine) and the preparer (curse-prepare). Extract it into the folder the server will live in. The README inside the archive has the exact first-run commands for that build.

First run

Run ./curse-server in the folder. The supervisor writes its server.toml, asks the engine for vanilla's server.properties defaults, and refuses to start until eula.txt says eula=true, exactly as the Java server does. The console, the web panel and the control API are the supervisor's; the game's own commands reach the engine's dispatcher as the server.

Configuration

Two files, two jobs. server.properties is vanilla's: port, MOTD, online mode, whitelist, view and simulation distance, player limit. server.toml is the supervisor's: where the engine lives, backups, updates, the panel and the control API. The generated reference in the source repository lists every key; the archive's README has the common ones.

Ports

The game listens on 25565 by default. The control API and the web panel listen on loopback only and are not exposed to the internet unless the owner asks for it. Open the game port in the firewall; leave the panel closed.

Backups and updates

The supervisor takes backups on its own schedule, keeps the last ones, and restarts the engine after a crash. A new build is applied only when the owner runs `curse-server update` (or clicks Update in the panel) — never by itself — and always with a backup first.

Players

Online mode is on by default: players join with their Microsoft account. Whitelist, operators, bans and IP bans use vanilla's files and vanilla's commands. The console accepts stop, save-all, list, op, whitelist, ban, kick and say; everything else goes to the game's command dispatcher.
